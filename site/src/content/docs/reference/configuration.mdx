The daemon reads `/etc/snitchhiker/daemon.toml` at start (another file with `snitchhikerd --config <path>`). Only root can change it. After a change, `sudo systemctl restart snitchhikerd`.

## The policy, changed while the daemon runs

Six settings are the node's **policy**: [`mode`](#mode), [`no_match`](#no_match), [`no_client`](#no_client), [`prompt_timeout_secs`](#prompt_timeout_secs), [`on_timeout`](#on_timeout) and [`retention_days`](#retention_days). Clients can change them while the daemon runs (the desktop app's Settings page, `snitchhiker policy set no_match=ask`). A setting changed that way takes effect at once and takes precedence over the file's until it is reset to it (`snitchhiker policy reset no_match`, or *Use daemon.toml's* in the app). Changes are recorded in the [history](/guides/rules/#history-and-undo) with who made them, and undone like rule changes.

A change that lets blocked connections through (to `monitor`, `no_match = "allow"`, or `allow` for `no_client` or `on_timeout`) is a [dangerous action](#step_up). `snitchhiker policy` shows the policy in effect and which settings a client changed.

Every key is optional; an empty or missing file means the defaults. Unknown keys are errors, so a typo doesn't go unnoticed. The packaged file sets `mode = "monitor"` and documents the rest.

```toml title="/etc/snitchhiker/daemon.toml"
mode = "enforce"
no_match = "ask"
no_client = "deny"
prompt_timeout_secs = 30
on_timeout = "deny"
fail = "closed"
```

## Deciding

### `mode`

`"enforce"` (default) or `"monitor"`. Enforcing, rules and `no_match` decide. In monitor mode everything passes, and each connection is recorded with what would have happened, to learn what a machine does before enforcing ([Quick start](/start/quick-start/)).

### `no_match`

What happens to a connection no rule decides. Default `"deny"`.

| Value | |
| --- | --- |
| `"allow"` | it passes |
| `"deny"` | its packet is dropped; the program times out |
| `"reject"` | its packet is dropped and its socket closed; the program fails at once |
| `"ask"` | it is held while clients are asked ([Prompts](/guides/prompts/)) |

### `no_client`

With `no_match = "ask"`: what happens when no client is listening for prompts. `"allow"`, `"deny"` (default) or `"reject"`.

### `prompt_timeout_secs`

How long a prompt waits for an answer: 1 to 3600 seconds, default `30`.

### `on_timeout`

What happens to a prompt's connections when nobody answered in time. `"allow"`, `"deny"` (default) or `"reject"`.

### `fail`

What happens to new connections while the daemon isn't running. Default `"closed"`.

| Value | |
| --- | --- |
| `"closed"` | Nothing new gets out. The table stays in place when the daemon stops, so its queue holds new connections until it is back. |
| `"open"` | Everything passes. The daemon's table is removed when it stops, and if the daemon dies without removing it, the kernel lets packets past the queue nobody reads. |

On a workstation `closed` is the point of a firewall. On a server you reach over the network, `open` keeps a crashed or stopped daemon from cutting you off; the unit restarts the daemon on failure either way.

## Rules

### `default_rules`

The built-in System folder, which allows loopback in the fallback tier ([Rules](/guides/rules/#the-system-folder)). Default `true`.

### `rules_dir`

Rule files root keeps, read at start and on reload, shown to clients as locked ([Rules](/guides/rules/#rule-files-root-keeps)). Default `/etc/snitchhiker/rules.d`. A missing directory means none.

## Names

### `learn_dns`

Learn the names of addresses from the DNS answers processes receive, so `host` conditions work ([How it works](/internals/how-it-works/#names)). Default `true`. Without it, rules can only name addresses and networks.

### `forward_from`

Bridges whose forwarded traffic is decided too. Containers on bridge networks and VMs on taps don't send through the host's own sockets: their packets are forwarded from the bridge, and Snitchhiker finds the program in the container that sent each one. Names, or prefixes ending in `*`. Default: `["docker0", "br-*", "podman*", "cni-*", "virbr*", "lxdbr*", "incusbr*"]` (Docker, Podman, CNI, libvirt, LXD and Incus). Empty: forwarded traffic is left alone, as on a router whose LAN clients aren't yours to ask about.

## Clients

### `client_group`

The group the client binaries are setgid to, and that the client socket belongs to. Default `"snitchhiker-ui"`.

### `trusted_clients`

Client binaries allowed on the client socket by path alone. Default none. Each must be owned by root, setgid to `client_group`, and in directories only root can write to; see [Security](/internals/security/#clients).

Clients are better registered with [`snitchhikerd trust-client`](/reference/cli/#trusted-clients), which also pins each to its SHA-256: packages register their client that way. The registry is `trusted-clients.toml` in the database's directory.

### `step_up`

What confirms a dangerous action a client asks for, such as a rule that allows every program to connect anywhere ([Security](/internals/security/#dangerous-actions-need-more-than-a-session)). Default `"polkit"`: polkit must authorize the client's process, usually with an administrator's password. `"off"`: the client's session is enough. Either way the attempt is audited.

## Remote devices

### `remote`

Accept paired devices over the network: phones, and the desktop app on other machines ([Phones and remote nodes](/guides/remote/)). Default `false`. The node's key is `node.key` next to the [database](#database), made the first time.

### `relays`

The relays the node keeps a connection to, so devices reach it behind NAT: the URLs of your own [`snitchhiker-relay`](/install/relay/) deployments. Default none: devices connect directly, which works on the same network or when the node's port is reachable.

### `remote_port`

The UDP port of the remote endpoint. Default `0`: any free port (fine with a relay). Set one to open it in a firewall or forward it from a router for direct connections from outside.

### `lan_discovery`

Announce the node on the local network (mDNS), so devices there find it without a relay, and [pairing codes](/guides/remote/#pairing-by-code) work there. Default `true`.

### `push_gateway`

The id of a push gateway: a [relay](/install/relay/#push-notifications) with its push service on, which `snitchhiker-relay push-id` prints there. It is reached through [`relays`](#relays). The gateway wakes your devices when a prompt waits for them and they aren't connected, and tells them when the node goes offline ([Phones and remote nodes](/guides/remote/#while-the-phone-sleeps)). Default empty: no gateway; devices learn of prompts only while connected.

### `offline_after_secs`

How long the node may be gone from its push gateway before your devices are told it is offline. Default `120`: a restart or an upgrade doesn't wake anyone.

### `prompt_routing`

Which clients are notified of a prompt; every admin client lists every prompt and can answer it either way ([Phones and remote nodes](/guides/remote/#who-is-notified)). Default `"all"`: every client, but [muted](/guides/remote/#who-is-notified) devices. `"escalate"`: the clients on this machine first; remote devices when no client here listens, when the users of the clients here are all away (their sessions locked or idle, as logind says), or once the prompt has waited [`escalate_after_secs`](#escalate_after_secs).

### `escalate_after_secs`

With `prompt_routing = "escalate"`: how long a prompt waits for the clients on this machine before remote devices are notified. Default `20`.

## Agents

### `agent_programs`

Programs allowed to propose rules on the agent socket ([Agents and MCP](/guides/agents/)), as patterns rules use (`glob:{home}/.local/share/claude/versions/*`). Default none: any program may propose, as any can trip a prompt; a person approves either way. With a list, an MCP server started by any other program is refused, and proposals show their agent as a known one.

## Alerts

### `alert_webhook`

A URL every alert is sent to as JSON, with an HTTP POST, besides the clients and devices: `{"node", "id", "time_ms", "kind", "title", "body"}`. Default empty: none. A delivery that fails is logged, not retried ([Alerts](/guides/alerts/#webhooks)).

### `alert_webhook_secret_file`

A file whose content (trimmed) signs each delivery: the header `X-Snitchhiker-Signature: sha256=<hex>` is the HMAC-SHA256 of the body with it, as GitHub signs its webhooks. Default none: unsigned.

## Queues and storage

### `queue`, `queues`

The first NFQUEUE queue number (default `0`) and how many queues there are (1 to 64, default `4`), each with its own deciding thread. The queue after the last is used for DNS answers when `learn_dns` is on. Change `queue` if another program on the machine uses queues 0 to 4.

### `database`

The SQLite database with the rules and the history. Default `/var/lib/snitchhiker/state.db`.

### `retention_days`

How long connection history is kept. Default `30`.
