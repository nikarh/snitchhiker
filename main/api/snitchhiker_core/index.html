The parts of Snitchhiker that do no I/O: the rule model, the matching engine, the query language and path generalisation. Shared by the daemon and the clients.

Modules§

blocklist
Blocklists: sets of domains and address ranges read from list files, for the list condition.
context
Who a connection’s sender is beyond the host (plan §5.10): a container’s identity, a VM’s, a network namespace’s name. Known exactly or not at all: a field that couldn’t be read is empty, and conditions on it don’t match.
destination
Destinations in rules: host name patterns, and networks (CIDR ranges and named aliases).
engine
Deciding a connection: rules compiled into an immutable, indexed set, evaluated without allocating.
envelope
Pre-authorized envelopes (plan §5.11): bounds within which an allow-listed agent’s proposals are approved without asking, for the agent’s session. “Agents working under ~/workspace may reach registry.npmjs.org, crates.io and *.crates.io.” Setting one is a dangerous action; a proposal that leaves the bounds in any way goes to a person.
generalize
Turning an executable’s path into a pattern that survives updates: path segments that look like versions or content hashes become *, and the user’s home becomes {home}.
lint
The lint and dedupe report over a rule set: duplicates, rules another one makes redundant, allow rules a deny always beats, expired rules, and, from what the node knows, rules never hit, on binaries any user can replace, or on binaries that are gone (with the pattern that would cover their new version).
opensnitch
Importing OpenSnitch’s rules (/etc/opensnitchd/rules/*.json, its documented format) as a rule file.
pattern
Text patterns of rules: exact strings, globs and regular expressions, matched without allocating.
proposal
Shaping agents’ proposals (plan §5.11). An agent only suggests: what reaches a person is a rule made from what the kernel saw where it can be (the program of the blocked connections, not the one the agent typed), refused when it would allow every program everywhere, and marked wherever it is broad, so that approving it needs a second look (and step-up).
query
The query language: one small language for rule search, event filters, Explorer pivots and alert conditions.
rule
The rule model: folders in a tree, and rules with conditions, as stored, exported and edited.
spec
Rules as people write them: the TOML (or JSON) of rule files, exports and managed rules.d files.
suggest
The rules a prompt offers, narrowest first: the first is what a quick answer creates.
system
The system firewall: the base packet filter the node keeps beside its application rules (inbound and forward policies, and rules over protocols, addresses, ports, interfaces and connection state), as a form over a fixed set of statements rather than raw nftables text.
