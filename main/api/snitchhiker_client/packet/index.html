Module packet 

Source
Expand description

Messages, each with a stream’s descriptor or none, over a SOCK_SEQPACKET unix socket: how the daemon and the desktop app talk to snitchhiker-remote (proto/snitchhiker/v1/bridge.proto). One message per packet, so a descriptor travels with exactly the message naming it, and a sender needs no lock: the kernel keeps packets whole. Each packet starts with a byte of its own (1), so an empty message isn’t taken for the end of the connection.
