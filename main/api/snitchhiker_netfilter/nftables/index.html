Source
Expand description

Snitchhiker’s nf_tables tables, written as netlink batches: the daemon’s (which queues new connections to it), and the system firewall’s (the base packet filter the user configures).

Only our own table is ever created, changed, read or deleted: nothing here lists the ruleset or touches another table, so another firewall’s large sets cost us nothing (a lesson from libnftables, which reads every interval set of every table before adding a set element).

encode_get_table
Writes a request for table name (only that one is read): the kernel answers with it, or with ENOENT. Returns the request’s sequence number.
encode_install
Writes the batch that (re)creates the table: in one transaction it is created, deleted (with whatever an older daemon or another tool left in it) and created again with its chain and rules, so packets see either the old table or the new one, never neither.
encode_remove
Writes the batch that deletes the table (created first, so deleting it never fails because it is missing).
encode_system
Writes the batch that (re)creates the system table, in one transaction as encode_install does.
