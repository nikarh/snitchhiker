Crate snitchhiker_relay 

Source
Expand description

snitchhiker-relay: the relay a user’s nodes and devices meet through when no direct path exists (plan §8.4). It is iroh’s relay server, configured from a TOML file: TLS by ACME, by certificate files, or none behind a reverse proxy that terminates it; optionally only listed endpoint ids may use it. Traffic through it stays end-to-end encrypted between node and device: the relay sees endpoint ids and opaque packets.

Modules§

fcm 🔒
Firebase Cloud Messaging, HTTP v1: high-priority data messages to the Play build of the app, with the user’s own Firebase project’s service account (plan §8.5). The account’s key signs a JWT (RS256) exchanged for an access token, kept until shortly before it expires.
push 🔒
The push gateway (plan §8.4, §8.5): an iroh endpoint of its own, homed on this relay, that nodes keep a stream open to (ALPN snitchhiker-push/1). On it a node says who to tell (its devices’ push targets), who to wake, and why it stops. The stream ending is the node going away; if it doesn’t come back within its offline_after_secs, its devices are told it is offline, and that it is back when it returns.
webpush 🔒
Web Push message encryption (RFC 8291, with the aes128gcm content coding of RFC 8188), for UnifiedPush endpoints: the push server only carries ciphertext, readable by the device that made the keys.
