Module remote 

Source
Expand description

Paired devices over the network (plan §8.2, §8.3, decision 0016): pairing with one-time secrets, and the devices’ connections, served as local ones are and closed when a device is unpaired.

The network itself is snitchhiker-remote’s, a service of its own (an unprivileged user, installed only where remote access is wanted): the daemon carries no network stack for it. The bridge connects to the daemon’s remote socket, which serves its user alone (the kernel’s peer credentials), and hands over each stream a peer opened, as a file descriptor with the peer’s id, which TLS proved. Everything else is decided here: whether the peer is a paired device, what it may do, whether its pairing secret is right.

A device is its key: only keys paired with the node are served. Pairing hands the node the device’s key: the device connects on the pairing ALPN and sends a one-time secret it got from a link, a QR code or a code (single use, 10 minutes, compared in constant time).
