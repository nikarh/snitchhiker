Module blocklists 

Source
Expand description

Blocklists from URLs and files (plan §5.8): fetched on a schedule, checked before they replace what was there, kept on disk so a restart without a network still has them, and named by rules’ list condition.

A list’s source is an https:// URL (plain HTTP isn’t taken: anyone on the path could change it) or a file in LOCAL_DIR, a directory only root writes: a client may add lists, and must not make the daemon (root) read any other file on the node, which the list’s entries, counts and errors would then show. A fetch is refused, and the version before kept, when the file is larger than blocklist_max_bytes, isn’t text, has no entries, or has more than a tenth of its lines that aren’t entries (an error page, a list in a format this doesn’t read). Unchanged lists aren’t downloaded again (If-None-Match).
