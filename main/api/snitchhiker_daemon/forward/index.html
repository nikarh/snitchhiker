Module forward 

Source
Expand description

Forwarded traffic (plan §5.10): a container on a bridge network, or a VM on a tap, sends packets that are forwarded from its bridge port; they never pass the host’s output hook. Their sender is found exactly:

  1. the packet’s link-layer source address, looked up in the bridge’s forwarding database, gives the bridge port it came in through;
  2. a veth port names the namespace of its peer (by a namespace id local to this namespace), which is mapped to the namespace’s inode through the processes in it; a tap port is a VM’s;
  3. the flow is then looked up as its sender recorded it in that namespace: the tuple before NAT, which is what the forward hook sees.

Each step is the kernel’s own table. A stale cache can only make the lookup miss (the flow must exist in the namespace it names, with that very tuple), never name the wrong sender; a miss is retried once afresh.
