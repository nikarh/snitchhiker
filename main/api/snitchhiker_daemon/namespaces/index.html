Module namespaces 

Source
Expand description

Network namespaces the daemon decides inside (plan §5.10).

  • Rootless containers’: their connections reach the host through a user-mode helper (pasta, slirp4netns), which makes them itself, so from the host only the container is known, not its program. A namespace is managed from the first connection of its helper the host sees (that one is decided as the container’s), for as long as the container’s process runs: a pidfd says when it ends.
  • Named ones (ip netns, a WireGuard namespace): nothing in them passes the host’s tables at all. Every namespace mounted under /run/netns is managed, from its mount to its unmount; the mount table’s change notifications say when either happens, so nothing is polled.

Inside, the daemon installs its table and binds a queue, on a thread that entered the namespace, and decides packets by the exact (namespace, flow) of the attribution programs, as on the host. A helper’s connections for a managed namespace are let through by the host’s layer, which would otherwise decide them a second time with less to go on. The namespace is let go when it ends (the daemon’s sockets would otherwise keep it alive). Its table is watched: something in there with CAP_NET_ADMIN deleting it gets it put back, and an alert.
