snitchhiker_daemon

Module runtime 

Source
Expand description

The running daemon: the table, the attribution programs, one deciding thread per queue, and the writer.

The packet path: receive → parse the headers → look the flow’s owner up (eBPF) → the process’s facts (cached) → the rules (an immutable set, swapped atomically on change) → verdict, and an event to the writer’s queue. Nothing on it waits for the database, and a full event queue drops the event (counted), never the verdict.
