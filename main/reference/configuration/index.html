Configuration

The daemon reads /etc/snitchhiker/daemon.toml at start (another file with snitchhikerd --config <path>). Only root can change it: clients can see the mode and the policy, not change them. After a change, sudo systemctl restart snitchhikerd.

Every key is optional; an empty or missing file means the defaults. Unknown keys are errors, so a typo doesn’t go unnoticed. The packaged file sets mode = "monitor" and documents the rest.

Deciding

Section titled “Deciding”

mode

Section titled “mode”

"enforce" (default) or "monitor". Enforcing, rules and no_match decide. In monitor mode everything passes, and each connection is recorded with what would have happened, to learn what a machine does before enforcing (Quick start).

no_match

Section titled “no_match”

What happens to a connection no rule decides. Default "deny".

Value
"allow" it passes
"deny" its packet is dropped; the program times out
"reject" its packet is dropped and its socket closed; the program fails at once
"ask" it is held while clients are asked (Prompts)

no_client

Section titled “no_client”

With no_match = "ask": what happens when no client is listening for prompts. "allow", "deny" (default) or "reject".

prompt_timeout_secs

Section titled “prompt_timeout_secs”

How long a prompt waits for an answer: 1 to 3600 seconds, default 30.

on_timeout

Section titled “on_timeout”

What happens to a prompt’s connections when nobody answered in time. "allow", "deny" (default) or "reject".

fail

Section titled “fail”

What happens to new connections while the daemon isn’t running. Default "closed".

Value
"closed" Nothing new gets out. The table stays in place when the daemon stops, so its queue holds new connections until it is back.
"open" Everything passes. The daemon’s table is removed when it stops, and if the daemon dies without removing it, the kernel lets packets past the queue nobody reads.

On a workstation closed is the point of a firewall. On a server you reach over the network, open keeps a crashed or stopped daemon from cutting you off; the unit restarts the daemon on failure either way.

Rules

Section titled “Rules”

default_rules

Section titled “default_rules”

The built-in System folder, which allows loopback in the fallback tier (Rules). Default true.

rules_dir

Section titled “rules_dir”

Rule files root keeps, read at start and on reload, shown to clients as locked (Rules). Default /etc/snitchhiker/rules.d. A missing directory means none.

Names

Section titled “Names”

learn_dns

Section titled “learn_dns”

Learn the names of addresses from the DNS answers processes receive, so host conditions work (How it works). Default true. Without it, rules can only name addresses and networks.

Clients

Section titled “Clients”

client_group

Section titled “client_group”

The group the client binaries are setgid to, and that the client socket belongs to. Default "snitchhiker-ui".

trusted_clients

Section titled “trusted_clients”

Client binaries allowed on the client socket by path alone. Default none. Each must be owned by root, setgid to client_group, and in directories only root can write to; see Security.

Clients are better registered with snitchhikerd trust-client, which also pins each to its SHA-256: packages register their client that way. The registry is trusted-clients.toml in the database’s directory.

step_up

Section titled “step_up”

What confirms a dangerous action a client asks for, such as a rule that allows every program to connect anywhere (Security). Default "polkit": polkit must authorize the client’s process, usually with an administrator’s password. "off": the client’s session is enough. Either way the attempt is audited.

Queues and storage

Section titled “Queues and storage”

queue, queues

Section titled “queue, queues”

The first NFQUEUE queue number (default 0) and how many queues there are (1 to 64, default 4), each with its own deciding thread. The queue after the last is used for DNS answers when learn_dns is on. Change queue if another program on the machine uses queues 0 to 4.

database

Section titled “database”

The SQLite database with the rules and the history. Default /var/lib/snitchhiker/state.db.

retention_days

Section titled “retention_days”

How long connection history is kept. Default 30.
