Snitchhiker

Snitchhiker is an interactive application firewall for Linux. Every new connection is attributed to the program that opens it and decided by your rules, or by you.

It is a daemon with a command line today; a desktop app and an Android app, for workstations and headless servers alike, are next. It learns what a machine does in monitor mode and turns that into rules.

Linux 6.5 or newer with BTF. MIT or Apache-2.0 (eBPF programs GPL-2.0 or MIT). Written in Rust.

What it is made of

Interception
The first packet of every new outbound connection waits in NFQUEUE while it is decided. Snitchhiker manages its own nftables table over netlink and never reads or changes anyone else’s.
Attribution
eBPF programs record which process opens each connection before its first packet leaves, so the program, its user and its container are known exactly. Names come from the DNS answers the process itself asked for.
Rules
Folders of rules on the program (with patterns that survive updates), host names, networks, ports and context. A precedence you can predict, and the rule that decided each connection in its history.
Prompts
A connection no rule decides can wait while you are asked. The narrowest rule is the first suggestion, and one answer settles every connection waiting on the same question.
Security
Only root and Snitchhiker’s own client binaries can control the daemon: the kernel says who connects, no secret on disk does. Other processes of your user can’t answer prompts or change rules.
Packages
Debian and Arch packages with a hardened systemd unit, for x86_64 and aarch64. The desktop app, the Android app and the relay for reaching machines behind NAT are in development.

How the pieces fit

 program ─connect─► kernel ─first packet─► NFQUEUE ─► snitchhikerd
            │                                        │  owner (eBPF) + rules
            └─ eBPF: who opened it ─────────────────►│  or a prompt to a client
                                                     ▼
                                     verdict ─► passes, or is dropped

The daemon runs as root, holds the rules and the history, and decides every new connection. The command line talks to it over a socket only root can open. The desktop app, verified by the kernel, uses another.

Install

Packages for x86_64 and aarch64 (glibc 2.35 or newer). Release files are signed. Details are in Install.

  • Debian / Ubuntu
  • Arch Linux

Then sudo systemctl enable --now snitchhikerd. It starts in monitor mode: everything passes and is recorded, and sudo snitchhiker learn turns what was seen into rules to review.
