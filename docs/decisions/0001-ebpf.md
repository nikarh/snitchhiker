# 0001. eBPF programs in C with CO-RE, loaded by aya

Status: accepted (M0)

## Context

Connections must be attributed to processes. The attribution has to be known when NFQUEUE hands over a flow's first
packet, without waiting or guessing, and one build has to run on every supported kernel (6.1 to the latest).

## Decision

- The programs are C (`crates/ebpf/bpf/`), compiled with clang at build time and embedded in the binary. Rust BPF
  (`aya-ebpf`) can't emit CO-RE field relocations yet; C can, so one object fits every kernel's struct layouts.
- Kernel structures are declared locally with only the fields read and `preserve_access_index`, no `vmlinux.h`.
  Their types must match the kernel's (e.g. `sin_addr` is `struct in_addr`, not `__be32`): a mismatched field fails
  its relocation, and the loader poisons the instruction (`call unknown#195896080`, 0xbad2310).
- The userspace loader is aya (pure Rust): it applies the relocations from the kernel's BTF and attaches fentry
  programs. Maps are read with byte-array keys and values, so no `unsafe` `Pod` implementations are needed.
- Hooks are chosen where the flow's addresses and ports are known *before* its first packet leaves:
  `tcp_connect()` (after the source port is chosen, before the SYN is built), and `udp_sendmsg()` /
  `udpv6_sendmsg()` (`inet_sendmsg()` binds the source port first). A kretprobe on `tcp_v4_connect()`, as OpenSnitch
  uses, runs after the SYN was queued, which would need waiting.
- License: `GPL-2.0-only OR MIT`, declared to the kernel as `"Dual MIT/GPL"`.

## Evidence

`attribution/*` scenarios: for TCP over IPv4 and IPv6 and for UDP `sendto`, the owner is in the map the moment the
packet is queued, with the right uid, name and executable (kernel 7.3).
